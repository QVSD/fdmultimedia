# FDM Multimedia v0.1.0-rc1 - Release Notes

First release candidate of the platform for a **controlled production pilot**. It contains no new product features after Phase 17Q; it makes the existing system installable from a clean checkout, secure by default in production, and operable.

## Scope

A media-to-social content platform: import video from a URL, inspect it, transcribe it locally with Whisper, find highlights (deterministic transcript scoring, with an optional Ollama analyser), select diverse highlights, cut clips and 1080x1920 verticals with FFmpeg, draft and schedule posts with Personas and Robots, publish (TEST provider for evaluation; Instagram and TikTok through their official APIs when explicitly enabled), collect analytics, and run bounded, human-governed adaptive optimisation, with an operator Operations page over the whole system.

## Supported deployment model

Single host, Docker Compose (`docker-compose.pilot.yml`), edge nginx terminating TLS with an operator-supplied certificate, one or two API replicas, one or two Workers, PostgreSQL 18, MinIO (built from the pinned upstream source), RabbitMQ (optional transport). Operator documentation: `docs/CONFIGURATION.md`, `docs/PILOT_CHECKLIST.md`, `docs/OPERATIONS.md`, `docs/DATA_AND_PRIVACY.md`. A loopback evaluation mode (plain HTTP on `localhost`) exists for trying it on one machine.

## Required and optional dependencies

Required: Docker with Compose v2; a DNS name and TLS certificate for production; 8 GB of RAM and disk for the volumes and a 5 GB image set. Built in: FFmpeg 4.4.2 and FFprobe (Ubuntu 22.04), OpenAI Whisper (CPU PyTorch) with the `base` model, Temurin JRE 21, PostgreSQL 18, nginx, MinIO. Optional: Ollama on the host (LLM copy and the semantic highlight analyser), Meta and TikTok developer credentials (real publishing).

Runtime components and licences (an inventory, not legal advice): Spring Boot, Flyway, PostgreSQL JDBC, AWS SDK for Java, commons-math3 (Apache-2.0, BSD-2/3, MIT); Angular, RxJS (MIT); PostgreSQL (PostgreSQL licence); nginx (BSD-2); RabbitMQ (MPL-2.0); **MinIO (AGPL-3.0; built from source, unmodified)**; FFmpeg (the Ubuntu build is GPL-enabled; the Worker invokes it as a separate process); OpenAI Whisper and PyTorch (MIT and BSD-3); Temurin (GPL-2.0 with Classpath exception). Review the AGPL and GPL terms before offering the platform to others as a service.

## Security model

OWNER and ADMIN are the only operators; everything else is a workspace member. Sessions are PostgreSQL-backed, `Secure`, `HttpOnly`, `SameSite=Lax`, shared across replicas, with CSRF on every mutation and an Origin check against `APP_PUBLIC_ORIGIN`. No CORS grants (same origin). Security headers and a strict CSP at the edge, HSTS in TLS mode, no server version disclosure, no stack traces or SQL in responses, login rate-limited to 10 per minute per address. The API starts only with real secrets (no development placeholders, https public origin, secure cookies, Flyway-only schema). Containers run non-root with read-only filesystems. Object storage is private: unsigned reads return 403 and presigned URLs are short lived. The application key can only touch its bucket. Provider tokens are AES-256-GCM encrypted and never given to Workers. SSRF protection blocks imports from private, loopback and metadata addresses.

## Backup and recovery

PostgreSQL: `scripts/backup-postgres.ps1` and `scripts/restore-postgres.ps1` (custom format, no secrets, restore into a fresh named database, sessions not restored). Object storage: mirror the bucket (`docs/OPERATIONS.md`). The two must be restored from the same point in time. The full restore into a second empty environment was rehearsed for this release: 10 assets and the whole operational state came back, presigned playback worked over TLS, and the application started on the restored database.

## Publishing caveats

TEST publishing is clearly marked "(non-real)" and live providers "(LIVE)" throughout the UI. Real Instagram and TikTok publishing were **not exercised** in the release rehearsal (no pilot accounts were used; no public post was made). An ambiguous provider outcome is never retried automatically; the Operations page raises it as a critical incident to verify by hand. Provider analytics need real publications and time (15 minutes to 7 days) and were not fabricated.

## AI prerequisites

Without Ollama everything deterministic works: transcription, V3 highlights, diversity selection, deterministic copy and campaign planning. LLM features need Ollama on the host with the model pulled, plus the settings in `docs/CONFIGURATION.md`; when it is absent the Worker does not advertise those capabilities and requests fail fast as "provider unavailable". Ollama was not part of the rehearsal.

## Adaptive automation defaults

Nothing adaptive is on by default. A new Robot has manual cadence and no adaptive policy row; the default proposal mode is `MANUAL_ONLY`; there are no execution authorizations, proposals or revisions on a fresh installation; applying a change or a rollback always needs a human action. Automatic proposals and pre-authorized execution exist but must be switched on per Robot by a person.

## Dependency review

`npm audit` (production and development): 0 vulnerabilities after updating Angular to 21.2.25 (the router had a high-severity SSR denial of service; the application does not use SSR). Container images were scanned with Trivy (HIGH and CRITICAL, fixable only): **API, web and Worker images: 0 findings.** To get there the API overrides Spring Boot 4.1.1's managed Tomcat (11.0.24 to 11.0.26: three critical access-control CVEs), Jackson (3.1.5 to 3.1.7) and the RabbitMQ client (5.30.0 to 5.34.0), the Worker uses Jackson 2.21.7, upgrades its OS packages, and the Whisper virtual environment ships without pip, setuptools and wheel (their vendored libraries carried findings). **MinIO** is built from upstream release RELEASE.2025-10-15T17-29-55Z (which fixes the MinIO privilege-escalation CVE of the previous release) but still bundles Go libraries with 10 packages of fixable HIGH or CRITICAL findings (gRPC, amqp091-go, x/net, x/crypto, OpenTelemetry, Prometheus and others) that only upstream can resolve. Exposure is limited: MinIO is never published except on the loopback interface and, in TLS mode, as an S3 endpoint behind nginx; the affected libraries sit in features the platform does not use (notification targets, gRPC and metrics servers). Treat it as an accepted, documented risk for the pilot, keep MinIO off the public internet beyond the proxied S3 port, and move to a maintained distribution when one is chosen. There is no Maven dependency scanner in the repository; the Trivy scan of the built image covers the packaged jar.

## Rehearsal results

All on a single Windows 11 workstation (Docker Desktop, 7.5 GB VM), loopback mode unless stated, with a real video (Blender's CC-BY "Sintel" trailer, 52 s, 854x480 H.264/AAC), no fixture data and no development database:

- **Clean checkout:** a copy of the repository without build artifacts, `scripts/pilot-init.sh`, `docker compose build --no-cache`, `up -d`: 7 services healthy, Flyway V1 to V45 applied once, first owner, workspace and Worker credential provisioned, 0 personas, Robots, assets, Jobs, publications or experiments, Operations `Healthy` with no incidents, understandable empty states on every page.
- **Pipeline (152 s end to end):** URL import and FFprobe inspection 3 s, Whisper transcription 10 s (4 segments, English), V3 highlights, diversity selection (1 of 2: the second candidate overlapped), clip 5 s, 1080x1920 vertical 17 s, draft ready, schedule, TEST publication `PUBLISHED`, Robot run reaching human review with a Persona. Provenance: publication to schedule to draft to highlight candidate to analysis to the source asset (the published vertical derives from a clip of the source).
- **Autonomy defaults:** no adaptive policy, proposal, authorization or revision exists on a fresh installation; the proposal-mode default is `MANUAL_ONLY`; the Robot has manual cadence.
- **Drills:** MinIO stopped and started (critical incident, acknowledged, auto-resolved), Worker stopped (stale then offline, incident, recovery), Worker SIGKILLed mid-render (lease expired, second attempt succeeded, one result row), two API replicas (cross-replica session and CSRF, rolling restart under 4,180 authenticated requests with 0 failures, full restart with the same session), PostgreSQL stopped (clean 503s, recovery with the same session).
- **TLS mode (self-signed certificate):** HTTP redirects to the canonical origin, HSTS and CSP, `Secure; HttpOnly; SameSite=Lax` cookie, foreign `Origin` 403, login rate limit (429 after 5 failures), unsigned storage 403, presigned `Range` 206 through the TLS storage proxy.
- **Backup and restore:** PostgreSQL dump and bucket mirror restored into a second empty environment: 10 assets back, application on the restored database, new sessions required.
- **Timing and resources (one small video, not benchmarks):** API p50 3 to 25 ms per call; vertical render 11.7 s and transcription 6.4 s on a 32-core host; Worker peak about 1.5 GB RAM; API about 590 MB per replica.

## Known limitations

- Users are provisioned from environment variables at first start; no self-service sign-up, invitation, password change or reset; recovery is an operator database action.
- No delete function for user data; retention is indefinite except for operational rows (`docs/DATA_AND_PRIVACY.md`).
- Single PostgreSQL and single MinIO; no automatic failover; PostgreSQL outage still means requests fail after about 10 s.
- The Worker image is large (4 GB); Whisper runs on CPU; `base` model only.
- The control plane is sized for tens of workspaces; OWNER and ADMIN are the operator roles; no external alerting, metrics export or tracing.
- Real Instagram/TikTok publishing, Ollama and a real public TLS certificate were not part of the rehearsal; TLS mode was exercised with a self-signed certificate (redirect, HSTS, secure cookies, storage proxy, restore) but its Worker traffic needs a certificate the JVM trusts.
- MinIO carries upstream-only dependency findings (see Dependency review).
- If the host sleeps, hourly schedulers read as stale on the Operations page until their next tick.
- npm and Docker base images move; rebuild periodically and re-run the dependency audit.

## Upgrade notes

From Phase 17Q (`10a6f10`, Flyway V45) to v0.1.0-rc1: no migration. The development Compose file now builds MinIO from source (the official image is no longer published) and serves the web container on port 8080 internally; recreate the stack with `docker compose up -d --build`. The Angular router was patched to 21.2.25 and the npm tree has no known vulnerabilities (`npm audit`).

## Fixed while preparing this release

- First account, workspace and Worker credential could not be created outside the development profile; added a fail-closed, idempotent first-run provisioning path.
- Real Whisper output can end a segment after the end of the media (a 52.2 s video produced a segment ending at 60 s), which made the API reject the whole transcription; the Worker now clamps to the media duration.
- The Worker reported free memory instead of available memory on Linux, so on a normal busy host the scheduler thought memory was exhausted and deferred media Jobs for minutes; it now reports `MemAvailable`.
- Unknown paths, wrong methods and malformed bodies answered 500 with an error log; they now answer 404, 405, 400 or 415 without logging a fault.
- MinIO images are no longer on Docker Hub, which broke a clean `docker compose up`; MinIO is built from the pinned source tag.
- Angular production build no longer inlines critical CSS through an inline event handler (it would violate the CSP) and ships no source maps.
- Added the production profile hardening, configuration validation, Origin check, edge security headers, login rate limit, non-root read-only containers, release versioning and the documents above.
